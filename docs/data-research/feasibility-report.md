# NUBI 공개데이터 타당성 보고서

조사 기준일: 2026-09-21 (Asia/Seoul)

## 조사 결과 요약

광주 버스 공식 운영 사이트의 실제 JSON 응답에서 실시간 도착정보와 노선별 실시간 위치정보 모두 `BUS_ID`와 `LOW_BUS`를 함께 제공하는 것을 확인했다. 관찰된 값은 `LOW_BUS=1`이 저상버스, `LOW_BUS=0`이 일반 차량을 의미한다.

따라서 핵심 질문인 “특정 운행 차량의 저상버스 여부를 공개데이터만으로 식별할 수 있는가?”의 현재 결론은 **A — 차량 단위 식별 가능**이다.

단, 정식 서비스 구현에 앞서 인증된 OpenAPI의 요청 계약과 기관의 데이터 품질 보장을 확인해야 한다. 이번 결과는 제품 도메인/API 개발을 승인하는 것이 아니라, 다음 기술 검증의 방향을 확정한 것이다.

## 사용 가능한 공개데이터

| 데이터 | 공식 제공기관/URL | 확인된 주요 필드 | 상태 |
| --- | --- | --- | --- |
| 버스 노선 | 전남광주통합특별시 [광주버스정보](https://www.data.go.kr/data/15157923/openapi.do) | `LINE_ID`, `LINE_NAME`, 방향명, 노선유형 | 공식 메타데이터 + 웹 응답 |
| 버스 정류소 | 동일 API 및 [정류소 파일데이터](https://www.data.go.kr/data/15128208/fileData.do) | `BUSSTOP_ID`, `ARS_ID`, 명칭, 좌표 | 공식 메타데이터 + 웹 응답 |
| 노선별 정류소 | 동일 API | `LINE_ID`, `BUSSTOP_ID`, 순서/좌표 | 공식 웹 응답 |
| 실시간 도착 | 동일 API | `BUS_ID`, `LOW_BUS`, `REMAIN_MIN`, `REMAIN_STOP`, 위치 정류소 | 공식 웹 응답 |
| 실시간 위치 | 동일 API | `BUS_ID`, `LOW_BUS`, 좌표, 현재 정류소 순번 | 공식 웹 응답 |
| 도시철도 역사/운행 | 광주교통공사 | 역 식별자, 위치, 역간거리, 소요시간 | 공식 문서 + 인증 없는 실제 호출 |

광주 버스 OpenAPI는 REST 및 JSON+XML을 제공하고, 공공데이터포털 페이지에는 무료·이용허락범위 제한 없음·개발계정 일 100회가 표시되어 있다. 인증키가 없으므로 포털 API의 직접 호출은 수행하지 않았다.

## 실제 호출 성공 여부

### 성공

- `https://bus.gwangju.go.kr/busmap/lineSearchListTemp2`
- `https://bus.gwangju.go.kr/busmap/stationSearchListTemp2?BUSSTOP_NAME=`
- `https://bus.gwangju.go.kr/busmap/lineStationListTemp2?LINE_ID=1`
- `https://bus.gwangju.go.kr/busmap/lineStationArriveInfoListTemp2?BUSSTOP_ID=2607`
- `https://bus.gwangju.go.kr/busmap/lineBusLocationListTemp2?LINE_ID=1`
- `https://bus.gwangju.go.kr/busmap/lineLowLocationListTemp2?LINE_ID=1`
- 광주교통공사 역사정보/운행정보 JSON API

### 미실행

- 공공데이터포털 정식 광주 버스 OpenAPI: 서비스키 필요. 인증키를 임의로 만들거나 우회하지 않았다.
- 따라서 인증된 API의 정확한 요청 파라미터, 실제 트래픽 제한 적용, 응답 헤더 기반 갱신 주기는 미확인이다.

## 식별자 관계

```text
LINE_ID       ── 노선
BUSSTOP_ID    ── 정류소
ARS_ID        ── 시민 표시용 정류소 번호
BUS_ID        ── 실시간 운행 차량
LOW_BUS       ── 차량 저상 여부 관찰값 (1/0)
CURR_STOP_ID  ── 차량 현재 위치 정류소
```

도착 응답에서는 `BUS_ID`·`LOW_BUS`·`LINE_ID`·`CURR_STOP_ID`가 한 레코드에 존재한다. 위치 응답에서는 `BUS_ID`·`LOW_BUS`·좌표·현재 정류소 순번이 한 레코드에 존재한다.

## 저상버스 차량 단위 식별 결과

**A — 차량 단위 식별 가능**

근거:

1. `LINE_ID=1` 위치 응답에서 `BUS_ID=5280`, `5284` 등의 차량이 `LOW_BUS=1`로 반환되고, `BUS_ID=5243`은 `LOW_BUS=0`으로 반환됐다.
2. `BUSSTOP_ID=2607` 도착 응답에서 `BUS_ID=775246`, `LINE_ID=1`, `LOW_BUS=1`, `REMAIN_MIN=5`가 한 레코드로 반환됐다.
3. 같은 도착 응답에 `LOW_BUS=0` 차량도 포함되어 단순히 노선 전체를 저상으로 표시한 것이 아님을 확인했다.

샘플 원문은 [`samples/`](samples/)에 저장했다.

## 현재 공개데이터만으로 구현 가능한 누비 기능

기관의 정식 API 계약 확인을 전제로 다음 기능의 기술적 기반이 있다.

- 노선·정류소·노선 경유 정류소 조회
- 좌표 기반 주변 정류소 후보 검색
- 정류소별 실시간 도착 예정 시간과 차량별 저상 여부 표시
- 노선별 현재 운행 차량 위치와 저상 여부 표시
- 관찰된 차량 응답을 이용한 노선·시간대별 저상 운행 현황 분석의 PoC
- 도시철도 역간 거리·소요시간을 이용한 후속 환승 데이터 연계

## 현재 구현하면 안 되는 기능

- 기관의 데이터 계약과 품질 기준을 확인하기 전의 운영용 실시간 저상버스 확정 안내
- 한 번의 조회를 근거로 휠체어 탑승 가능을 보장하는 경로 추천
- `LOW_BUS` 표본만으로 노선 전체의 저상버스 공급률·운행대수를 확정하는 분석
- 차량 교체·예비차·운행중단을 고려하지 않은 장기 차량 마스터
- 인증·호출 제한·재시도 정책이 정해지지 않은 공공 API 수집 서버

## 부족한 데이터

- 정식 OpenAPI의 서비스별 요청/응답 스키마와 버전 정책
- `BUS_ID`의 영속성 및 `carNo`와의 공식 매핑
- 차량 마스터: 차량번호, 차종, 저상 여부, 운송사업자, 유효기간
- 배차·운행계획과 실제 차량 배정 관계
- 데이터 생성시각, 수집시각, 지연·결측·오류 코드의 공식 의미
- 저상버스 운행현황의 기준일·노선별 총 운행대수·저상대수·운행률
- API SLA, 초당/일 호출 제한, 장애·점검 공지 방식
- 과거 이력·대량 다운로드·재배포 허용 범위

## 기관에 요청해야 할 항목

1. 광주 BIS 공식 OpenAPI 가이드와 서비스별 운영 URL, 파라미터, 필드 정의, 버전·폐기 정책
2. `BUS_ID`가 차량 단위로 안정적으로 유지되는지와 `carNo`·차량등록번호와의 매핑 제공 여부
3. `LOW_BUS`의 공식 코드표, 공백/오류/예비차/운행중단 처리 규칙
4. 실시간 위치·도착·저상버스 정보의 공통 생성시각과 허용 지연시간
5. 노선별 차량 배정표 및 기준일별 저상버스 보유·운행 통계
6. 호출 제한, 장애 대응, 데이터 보존·재사용·재배포 조건
7. 휠체어 이용자에게 저상버스 탑승 가능을 안내할 때 필요한 면책·표시 기준

## 다음 개발단계 제안

1. 기관에서 정식 OpenAPI 가이드와 차량 마스터/배차 자료를 확보한다.
2. 인증된 샌드박스 또는 개발키로 동일 차량의 위치·도착 응답을 시간창별로 수집한다.
3. `BUS_ID`·`LOW_BUS`의 일관성, 결측률, 지연, 차량 교체 사례를 회귀 검증한다.
4. 그 결과가 유지될 때에만 원시 응답 저장·정규화·저상버스 표시 API를 설계한다.

현재 단계에서는 위 조사 결과 보고 후 추가 도메인/API 구현을 진행하지 않는다.
