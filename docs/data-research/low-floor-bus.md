# 저상버스 차량 단위 식별

## 핵심 질문

실시간 위치 또는 도착정보에서 받은 특정 차량을 저상버스 데이터와 연결해 현재 도착 차량의 저상버스 여부를 판별할 수 있는가?

## 확인한 관계

현재 공식 버스정보 사이트의 실제 응답에서는 별도 조인 없이 다음 필드가 한 차량 레코드에 함께 존재한다.

```text
BUS_ID  -> 특정 운행 차량
LOW_BUS -> 해당 차량의 저상 여부 (관찰값: 1=저상, 0=일반)
```

도착정보와 위치정보 모두에서 `BUS_ID`와 `LOW_BUS`를 확인했다.

### 사례 1: 실시간 위치

`LINE_ID=1` 위치 응답에서 다음과 같은 레코드를 확인했다.

- `BUS_ID=5280`, `LOW_BUS=1`, 좌표 및 현재 정류소 순번 포함
- `BUS_ID=5284`, `LOW_BUS=1`, 좌표 및 현재 정류소 순번 포함
- `BUS_ID=5243`, `LOW_BUS=0`, 좌표 및 현재 정류소 순번 포함

근거 응답: [`samples/bus-position-line-1.json`](samples/bus-position-line-1.json)

### 사례 2: 실시간 도착

정류소 `BUSSTOP_ID=2607` 도착 응답에서 다음을 확인했다.

- `BUS_ID=775246`, `LINE_ID=1`, `LOW_BUS=1`, `REMAIN_MIN=5`
- 같은 응답에 `LOW_BUS=0`인 다른 차량도 존재

근거 응답: [`samples/bus-arrival-2607.json`](samples/bus-arrival-2607.json)

## 결론: A — 차량 단위 식별 가능

공식 운영 사이트의 실제 응답 기준으로는 특정 실시간 차량 레코드의 `BUS_ID`와 `LOW_BUS`가 함께 제공되어 차량 단위 저상버스 여부를 판단할 수 있다. 따라서 현 단계의 핵심 기술 질문에는 **A**로 답한다.

## 남은 리스크

1. 인증된 공공데이터포털 OpenAPI의 정확한 요청 주소·파라미터·스키마는 서비스키 없이 실행 검증하지 못했다.
2. `*Temp2` 경로는 공식 웹 화면의 내부 조회 경로이므로 외부 연동 계약·호출 제한·폐기 정책이 문서화되어 있는지 기관 확인이 필요하다.
3. `BUS_ID`의 차량 교체·운행 회차별 안정성, `LOW_BUS` 값의 공백/오류/지연 처리 규칙이 공개 문서에 명확히 보이지 않는다.
4. 위치 조회와 도착 조회를 별도 호출하면 시점이 달라질 수 있다. 생산 시스템에서는 원본 수집 시각과 응답 시각을 저장하고 동일 시간창 내에서만 매칭해야 한다.
5. 표본은 조사 시점의 동적 응답이며, 운영 데이터 품질과 장기 일관성을 보장하는 통계 검증은 아직 하지 않았다.

## 제품 범위에 미치는 영향

A이므로 이론적으로는 `현재 도착 예정 차량의 저상 여부`를 제공할 수 있다. 다만 기관 확인 전에는 이를 확정적인 접근성 보장으로 표현하지 말고, 조회 시각·데이터 출처·오류 가능성을 표시해야 한다. 이 조사 직후에는 제품 도메인/API를 추가하지 않는다.
